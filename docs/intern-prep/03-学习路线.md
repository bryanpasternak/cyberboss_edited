# Cyberboss 学习路线

## 规则

- 简历里不写的，暂时不学；
- 一次只学一个问题；
- 每次 20～40 分钟；
- 每次必须留下一个可检查的输出；
- 卡住 10 分钟就记录问题，不继续挖洞；
- 不允许从 `app.js` 第一行开始通读。

## 总路线

| 顺序 | 要回答的问题 | 学完后的产物 |
|---:|---|---|
| 0 | 目标 JD 真正在要什么？ | 3 个 JD + 高频词 |
| 1 | 一条消息怎样进入 Agent 又回来？ | 一张调用链图 |
| 2 | 为什么回复不会串到错误会话？ | thread/turn/target 解释 |
| 3 | Agent 怎样调用 Reminder 工具？ | 一张 Tool Call 链路图 |
| 4 | Reminder 到期时线程正忙怎么办？ | 一个时序图 |
| 5 | 共读怎样阻止 Agent 剧透？ | 三个门禁规则 |
| 6 | 系统出了问题怎样排查？ | 两个故障案例 |
| 7 | 后端基础有哪些缺口？ | 按 JD 生成的补课表 |

## 阶段 0：先拿真实 JD 校准

### 任务 0A｜20 分钟

找 3 个你愿意投的 JD。

只做：

- 保存链接或截图；
- 标出岗位名称；
- 标出城市、实习时长和到岗要求。

不做：

- 不查每个技术名词；
- 不判断自己配不配；
- 不立刻改简历；
- 不开始学算法。

验收：有 3 个完整 JD。

## 阶段 1：消息主链路

### 任务 1A｜30 分钟

问题：

> 一条微信消息怎样进入 Codex，然后回到同一个微信聊天？

只读：

1. `docs/architecture.md`
2. `src/core/app.js` 中的 `runChannelPollLoop`
3. `handleIncomingMessageFromChannel`
4. `handlePreparedMessage`
5. `dispatchPreparedTurn`
6. `src/core/stream-delivery.js` 中的 `handleRuntimeEvent`

输出一张图：

```text
Weixin
→ getUpdates
→ normalizeIncomingMessage
→ handlePreparedMessage
→ dispatchPreparedTurn
→ Runtime Adapter
→ Runtime Event
→ StreamDelivery
→ sendText
```

验收问题：

> 回复为什么知道应该回给哪个用户和哪个通道？

### 任务 1B｜25 分钟

区分下面五个词：

- workspace
- binding
- thread
- turn
- reply target

输出：每个词只写一句自己的解释。

### 任务 1C｜30 分钟

比较 Codex 与 Claude Code Runtime Adapter。

只回答：

- 它们上层接口哪里相同？
- 底层连接方式哪里不同？
- 为什么切换 Runtime 不需要重写微信通道？

## 阶段 2：工具和主动任务

### 任务 2A｜30 分钟

沿着一个工具学，不看全部 28 个：

```text
cyberboss_reminder_create
→ Tool Host
→ JSON Schema 校验
→ Reminder Service
→ Reminder Queue
```

输出：一份合法输入 JSON，加一句每层负责什么。

### 任务 2B｜30 分钟

问题：

> Reminder 到期后为什么不是直接发送固定文案，而是重新唤醒 Agent？

只读：

- `reminder-queue-store.js`
- `flushDueReminders`
- `system-message-dispatcher.js`

输出：五步时序。

### 任务 2C｜30 分钟

问题：

> 用户消息和 System Message 同时到达时，谁先执行？

只读：

- `turn-gate-store.js`
- `routePreparedInbound`
- `flushPendingInboundMessages`
- `flushPendingSystemMessages`

输出：画出 A 正在执行、Reminder 到期、用户又发送 B 的顺序。

## 阶段 3：共读门禁

### 任务 3A｜30 分钟

问题：

> 快速翻页为什么不会让 Agent 读完整本书？

只读：

- `read-along/docs/ARCHITECTURE.md`
- `handleBeat`
- `evaluatePending`
- `pushedRanges` 相关判断

输出：写出停留阈值、已读区间和重复过滤三条规则。

### 任务 3B｜25 分钟

问题：

> Prompt 里写“不要剧透”和代码门禁有什么区别？

输出：用一个恶意或错误 Tool Call 举例。

## 阶段 4：测试和故障排查

### 任务 4A｜30 分钟

任选一个测试文件：

- `stream-delivery.test.js`
- `turn-gate-store.test.js`
- `codex-reconnect.test.js`

输出：

1. 测试准备了什么；
2. 触发了什么；
3. 最终断言什么风险不会发生。

### 任务 4B｜30 分钟

准备两个故障案例：

- 模型有输出，但微信没有收到；
- 用户连续发两条消息，第二条没有被处理。

输出：每个案例写三步排查顺序。

## 阶段 5：后端基础补齐

这一阶段必须等真实 JD 到手后再拆。通常从以下内容中选择，不全部同时学：

- Java/Python 主语言；
- REST API；
- MySQL、索引、事务；
- Redis；
- 消息队列；
- Linux、网络和操作系统；
- 日志、测试和部署；
- 数据结构与算法。

Cyberboss 可以帮助理解异步 I/O、队列、会话状态和模块分层，但数据库、缓存及标准 Web 框架需要用苍穹外卖或单独小练习补齐。
