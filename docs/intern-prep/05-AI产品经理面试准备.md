# AI 产品经理培训生 · 面试准备包

> 这份东西只服务一个目标：让你在面试里**看起来已经是个产品经理了**。
> 培训生岗不要求你有经验，要求你有三样东西：思考力（结构化）、表达力（讲清楚）、技术理解力（听得懂工程师）。

---

## 0. 先认清考官在找什么人

| 他们想验证的 | 对应你简历里的证据 | 面试里要放大 |
|---|---|---|
| 对 AI 有热情、真关注 | Cyberboss 是你自己发起做的 | 讲出"你主动探索"的细节，不是被布置的任务 |
| 逻辑和结构化思维 | 项目里你拆需求、定方案、定验收 | 用框架答题，别想到哪说到哪 |
| 写作与表达 | RAG 论文、共读批注机制 | 回答里有"背景—问题—方案—结果"的完整骨架 |
| 技术理解力 | 28 个工具、MCP、Prompt、RAG | 能说清"模型会错，产品怎么兜底" |
| 学习速度 | 从零把 Cyberboss 做到能跑 | 讲"我怎么从不会到会"的过程 |

**记住一句总叙事：**
> 我做过一个从 0 到 1 的 AI 产品，我从真实用户（包括我自己）的痛点出发，独立完成了需求定义、方案设计和迭代验证。AI 让我的实现变快了，但定义什么是对的，始终是我的判断。

## 1. 通用答题框架（背熟，所有题都能套）

### 框架 A：讲项目 / 讲经历 → STAR
```
情境(S)：为什么会有这件事，用户/背景是谁
任务(T)：我要解决的具体问题是什么
行动(A)：我怎么定义需求、做方案、推落地（少讲别人，多讲"我"）
结果(R)：做成了什么，怎么验证的，后续怎么迭代
```
产品岗的 STAR 和开发岗的区别：**行动里优先讲"我判断了什么"，不是"我写了什么"。**

### 框架 B：讲产品判断 → 三段式
```
① 用户价值：谁，在什么场景，痛点是什么，解决到什么程度
② 技术可行性：模型能不能做好？做不到的部分产品怎么兜底？
③ 成本与收益：值不值得做？冷启动怎么办？竞品差在哪？
```

### 框架 C：被问弱点 / 不足 → 安全公式
```
① 诚实承认一个真实局限（不装完美，但别说致命伤）
② 给出你已经在做的改进动作
③ 反问一句"如果重做，我会更早做 X"
```

## 2. 高频问题与参考回答

### 板块一：动机与自我定位

**Q1 为什么想当 AI 产品经理？**
- 想听：真实动机，不是"AI 是风口"。
- 结构：触发点 → 我做了什么 → 为什么是"产品经理"而不是"工程师"。
- 参考：从 Cyberboss 开始，我发现 AI 第一次能"主动参与人的生活"而不只是回答问题，这个变化让我兴奋；而它要落地，关键不是写更多代码，而是搞清楚"人到底需要 AI 替他们做什么"。这是产品问题，是我最想干的事。

**Q2 你没产品实习经验，为什么录你？**
- 想听：不回避 + 可迁移的证据。
- 参考：我没有产品实习，但我完整做过一个产品——Cyberboss 从需求、方案、验收到迭代，整个过程我做的就是产品经理的事；我有技术背景（RAG、Agent），能听懂工程师、判断可行性，这是纯产品背景的人要补很久的短板；而且我学得快，证明是把这个项目从零做到能长期运行。

**Q3 你最近在关注 AI 的什么？**
- 想听：持续关注 + 有自己的观点，不是背新闻。
- 准备 3～5 条近期动向（见第 4 部分清单），每条带一句"这让我觉得…"。选一个跟你项目相关的方向切入最加分，比如 Agent 应用生态、AI 陪伴/个人助理。

### 板块二：项目深挖（重头戏，占一半时间）

**Q4 介绍一下你的 Cyberboss 项目。**
- 产品语言，先讲用户再讲产品，最后才讲技术。
- 参考（一分钟版）：
> 我发现 ADHD 人群有个典型困境——知道该做什么，但很难启动、很容易中断，需要外部监督。市面上 AI 助手都是被动式的，你问它才答，帮不了这个忙。所以我做了 Cyberboss：把 AI 接到微信/Telegram 这些用户本来就在的渠道上，让它能主动提醒、定期唤醒用户，形成外部监督。它已经真实运行、持续迭代。我负责需求、方案和验收，AI 负责大量实现。

**Q5 "主动式"和"被动式"的差别，为什么用户需要主动？**
- 想听：需求洞察，不是技术。
- 参考：被动式等用户开口，只服务"已经启动的人"；ADHD 用户卡住的是"启动"本身，所以需要产品主动介入节奏。主动式不是功能，是产品形态——它要求 AI 有"何时该打扰用户"的判断。

**Q6 你做了多少用户调研？怎么证明需求真实？**
- 诚实 + 会往产品方法上靠。别吹大规模访谈。
- 参考：真实用户是长期使用的、最深的样本；我是通过"我自己就是目标用户 + 长期实际使用"做的最小化验证，用真实使用反馈驱动迭代，这是 MVP 的思路。但我要承认局限——样本量小、没有系统访谈和数据埋点；如果重新做，我会访谈更多 ADHD 用户、做量化埋点来验证需求强度。

**Q7 共读模块的"防剧透"是怎么想到的？为什么重要？**
- 这是你最有辨识度的点，一定要讲。能体现你想得到用户注意不到的细节需求。
- 参考：一起读书时，如果 AI 在用户还没读到的地方提前"剧透"，阅读体验就毁了，信任也没了。所以我做了"已读门禁"——用户看到哪，AI 才能读到哪。这个约束不是靠提示词，而是在数据访问层做限制，因为只有代码层面的门禁才可靠。这让我意识到：AI 产品的体验边界，很多要靠产品设计而不是模型自觉。

**Q8 项目里最大的困难 / 一次失败？**
- 参考（AI 协同开发的边界）：项目大量用 AI 写代码，最大的挑战不是"让 AI 干活"，而是"怎么确认它干的是对的"。我把它当成真正的产品经理工作：定义需求、拆验收标准、用运行结果和日志定位问题、推动修复。这让我理解了——AI 提高的是实现速度，但判断什么是对的，永远要靠人。

**Q9 如果重新设计 Cyberboss，产品上你会升级什么？**
- 想听：迭代思路（答技术升级就偏了）。
- 方向任选 2 个展开：埋点与数据驱动（留存、唤醒成功率）；把单用户扩展到多用户做验证；引入用户主动可控的"打扰强度"设置；商业化路径；全球化。

### 板块三：产品基础题

**Q10 你最喜欢的 AI 产品是？改进它，改什么？**
- 准备 1～2 个深度案例（建议选 AI 陪伴/助理类，跟你有共鸣）。分析维度：核心用户、价值点、商业模式、痛点、我会改什么。

**Q11 怎么判断一个 AI 功能值不值得做？**
- 三段式框架（见上）：用户价值 → 技术可行性 → 成本收益。补充：模型做不到的部分，有没有产品层兜底；有没有数据/冷启动问题。

**Q12 模型经常答错 / 幻觉，产品怎么办？**
- 想听：承认 AI 不完美 + 产品层缓解，不是"换个更强的模型"。
- 缓解手段库（挑着讲）：
  - 限制能力边界：只让 AI 做它擅长的事；
  - RAG / 工具调用：不猜数据，去查；
  - 校验与兜底：关键场景给规则校验、人工兜底；
  - 用户可控：标注"AI 生成"、提供来源、允许纠错；
  - 错误反馈闭环：把用户纠错收回来做持续优化。

**Q13 怎么给一个 AI 功能定评测标准？**
- 别只说准确率。维度：任务完成率、用户满意度、延迟、成本、误用/风险率，以及"能否用真实数据说话"。

### 板块四：AI 通识（被追问的兜底）

**Q14 大模型是怎么工作的？（一句话解释）**
- 参考：可以理解为"读了海量文本、学会了预测下一个词该是什么"的生成器。你给它上文，它生成最可能的下文，把 AI 产品里的回答、总结、工具调用，都是这个机制的产物。

**Q15 LLM / Agent / RAG / MCP 是什么，区别？**
- LLM：底层大脑，会"想"；
- Agent：会"做事"的 LLM 应用——有工具、能规划、能行动、能看结果调整；
- RAG：检索增强生成，先把外部知识查出来再喂给模型，减少幻觉；
- MCP：工具调用的统一协议，让 Agent 能用一套标准方式接各种外部能力。
- 一句话串：Agent 用 RAG 拿到知识，用 MCP 调用工具，背后是 LLM 在做判断。

**Q16 为什么 Agent 会幻觉？怎么减少？**
- 成因：模型本质是在预测，不是查事实；训练数据有噪音。
- 缓解：RAG 给事实、工具调用给实时数据、限制自由度、明确"不知道就说不"。

**Q17 什么是数据驱动决策？**
- 埋点 → 定指标 → 提假设 → 小步实验 → 看数据 → 迭代或放弃。

### 板块五：行为 / 场景题

**Q18 和工程师意见不合怎么办？**
- 结构：先理解对方顾虑（技术成本/风险）→ 对齐共同目标 → 用数据和用户反馈说话 → 必要时换方案或妥协。核心是"不证明自己对，而是一起让产品成"。

**Q19 需求太多，怎么排优先级？**
- 参考：影响面 × 价值 × 成本 × 风险，MVP 思维先做核心闭环，砍掉可后置的。

**Q20 一个 AI 产品上线后没人用，你怎么分析？**
- 结构：先别急着改功能——定位是"没人知道"（入口/渠道）还是"知道了不用"（价值没击中）还是"用了留不住"（体验/完成度）；看激活、留存、流失环节的数据；做几个用户访谈；形成假设 → 验证 → 迭代。

### 板块六：反问环节（一定要准备）

- 反问体现你的思考，不要只问"几点下班"。
- 建议问：
  - 培训生会参与哪个具体产品的哪个环节？
  - 团队目前做 AI 产品最大的挑战是什么？
  - 你们怎么评估培训生转正？

## 3. 知识清单（按优先级，易读版）

### 🔴 A 档：必须能讲清楚（面试必问）
| 知识点 | 讲到什么程度 | 一句话版本 |
|---|---|---|
| Cyberboss（你的项目） | 产品 + 用户 + 我的判断 | 面向 ADHD 人群的主动式 AI 陪伴产品，从 0 到 1 |
| RAG 医疗问答 | 产品视角 + 一句话原理 | 把医学知识结构化后检索喂给模型，做专业问答 |
| 大模型工作原理 | 能用类比解释 | 学会预测下一个词的海量文本生成器 |
| Agent | 概念 + 例子 | 会调工具、能规划、能行动的 LLM 应用 |
| Prompt Engineering | 概念 + 你的实践 | 把目标、约束、格式讲清楚并验证 |
| 工具调用 / MCP | 概念 + Cyberboss 例子 | 让模型按结构化 Schema 调用真实能力 |

### 🟡 B 档：知道定义，能举一句例子（被追问不慌）
- Token（模型处理文本的最小单位）、上下文窗口（一次能"记住"多长）
- 温度 temperature（控制随机性，越高越发散）
- 微调 vs RAG（改模型本身 vs 喂外部知识）
- 向量数据库 / embedding（把文字变成"语义坐标"，用于相似检索）
- SFT / RLHF（知道是"训练出好模型"的两个阶段即可）
- 埋点、DAU/MAU、激活率、留存率、转化率（产品指标，必须会用）
- 全球化 / 本地化（JD 提到 global，准备一句话：产品如何适配不同文化的用户习惯）

### 🟢 C 档：面试前一晚突击
- 最近 3～5 条 AI 大新闻 + 你的一句看法（见第 4 部分）
- 这家公司是谁、他们的产品线、他们的 AI 产品
- 2 个你欣赏的 AI 产品，能各讲 3 分钟

## 4. 考前背诵卡（最后一天只看这里）

**一句话自我介绍：**
> 我是 [学校+专业] 的 [年级]。我做过一个从 0 到 1 的 AI 产品 Cyberboss——面向 ADHD 人群的主动式 AI 陪伴产品，我负责需求、方案和验收；还有一个 RAG 医疗问答科研项目，正在投论文。我最大的特点是：对 AI 产品有真实的热情，而且动手验证过。

**一句话版 Cyberboss：**
> 把 AI 接入微信/Telegram，让它主动提醒和陪伴 ADHD 用户；核心差异是"主动"——不是等用户来问。

**三个必会词（30 秒版）：**
- Agent = 会做事、会调工具的 AI 应用
- RAG = 先查知识再回答，减少瞎编
- 幻觉 = 模型在"预测"不是在"查事实"，用 RAG、工具和边界来兜底

**三个万能开头：**
- 讲项目：`这件事的起因是…我负责的是…做成后我验证了…`
- 讲产品：`用户是…场景是…痛点是…技术能做到…成本是…`
- 被挑不足：`我承认…这是我真实的局限；我正在…；如果重来我会更早…`

**一个不能犯的错误：**
- 别让面试官觉得你只是"用 AI 做了个玩具"。每个问题都要落在"我判断了什么、我定义了什么是对的"。
