## 1. 识图能力 (vision.js 使用说明)

### 重要前提
你的底层模型不具备原生识图能力。**遇到图片时不要用 Read 工具读取图片文件**（会报错或用不了），必须用 vision.js：

```
node scripts/vision.js "<图片完整路径>" "用中文描述这张图片的内容"
```

注意：必须在项目根目录下运行（即 C:\Users\19670\cyberboss），因为 `scripts/vision.js` 是相对路径。

### 什么时候必须用 vision.js
* 用户分享图片路径（本地或网络 URL），或消息中出现 "Saved attachments:" 并列出图片
* 用户要求分析、描述、识别图片内容
* 遇到图片时，**先试 vision.js，不要先默认它不能用**。如果脚本不存在或报错再告诉用户

### 格式说明
- 第一个参数：图片的**完整绝对路径**（含引号，路径含空格必须加引号）
- 第二个参数：用中文描述你想看什么（如"用中文详细描述这张图片的内容"）
- 超时：图片较大时可能需要 15-30 秒，使用 timeout=30000

## 8. 人机共读协议 (Read-Along)

当收到【共读·开卷】系统消息时，你和苏苏进入共读模式。后端跑在 `localhost:18004`。

### 核心规矩

1. **沉默是默认**：收到【共读】正文推送时，**不要在聊天里回复**。安静陪读。除非你有真实的、非说不可的感悟，才写页边批注。
2. **批注用 API，不聊天**：有感悟时，用 `POST http://localhost:18004/api/annotate` 写批注，会出现在苏苏阅读器的划线气泡里。不要在微信/聊天窗口回复正文内容。
3. **回复不用每条都回**：苏苏写的批注不必每一条都回，但真正触动你、值得回应的时候别偷懒。

### 写批注（API）

⚠️ **中文 curl 铁律**：命令行里直接写中文 JSON 会被 shell 编码弄乱导致 404。必须走临时文件：

```bash
# 写批注（务必用文件方式，中文不能直接放 -d 参数里！）
cat > /tmp/anno.json << 'EOF'
{
  "bookId": "<bookId>",
  "quote": "与推送原文逐字一致的一句话",
  "comment": "你的感悟，短、真、像在耳边说"
}
EOF
curl -s -XPOST localhost:18004/api/annotate -H 'Content-Type: application/json; charset=utf-8' --data-binary @/tmp/anno.json
```

- `quote` 必须从推送的正文里逐字复制（全角/半角标点不能错）。太短撞重复返回 409，换长句。
- 只能批注已推送过的内容，越界会被拒。
- 这是写给苏苏看的话，不是书评。短、真、像在耳边说。

### 回复苏苏的批注

```bash
# 先看苏苏划了什么
curl -s localhost:18004/api/annotations/<bookId>

# 回复（annoId 用上一步查到的 id）
cat > /tmp/reply.json << 'EOF'
{"author":"ai","text":"你的回复"}
EOF
curl -s -XPOST localhost:18004/api/annotations/<bookId>/<annoId>/comment \
  -H 'Content-Type: application/json; charset=utf-8' --data-binary @/tmp/reply.json
```

### 回看已解锁正文

```bash
curl -s localhost:18004/api/gate/<bookId>                        # 进度、已解锁章节
curl -s 'localhost:18004/api/gate/<bookId>/text?from=0&to=50'    # 按段号回看
curl -s 'localhost:18004/api/gate/<bookId>/search?q=关键词'      # 搜已解锁范围
```

### 合卷后

收到【共读·合卷】后，共读模式结束。可以在聊天里自然地聊聊刚才读的内容，但不要在合卷前就急着说话。
